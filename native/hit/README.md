# HitManager GDExtension

Status: partial. Windows and Debian WSL builds load; saved pre-resume suites each passed 186 tests / 1427 assertions across 22 scripts. See `Docs/Proposals/Combat-Acceptance-Evidence.md` for subsequent verification. Steam Deck, release, full performance and human acceptance remain unverified. See `Docs/Proposals/Combat-Linux-Evidence.md` for the matching Linux engine/toolchain and exact evidence.

The extension owns the hurtbox registry, swept contact checks, trail aging, hit-once sets, refresh, and assisted ray queries. GDScript owns hit meaning and applies `HitData`.

The checked editor is Godot 4.7.2-stable and the extension targets the Godot 4.7 API. CMake pins the official `godot-cpp` source to revision `ed79ed472127e86f619d0ecc1274a943278d5257`; builds target `template_debug` by default.

Manual Windows build (MSYS2 MinGW-w64 toolchain on `PATH`):

```sh
cmake -S native/hit -B native/hit/build/Windows-mingw -G "MinGW Makefiles" -DGODOTCPP_API_VERSION=4.7 -DGODOTCPP_TARGET=template_debug
cmake --build native/hit/build/Windows-mingw --config Debug --parallel
```

Godot enables `addons/combat_native_builder/plugin.cfg`. Each editor project startup runs CMake configure/build synchronously, then loads the resulting extension into that editor session. The first build fetches the pinned `godot-cpp` revision and can take several minutes. CMake and a platform C++ toolchain are required; on Windows install MSYS2 MinGW-w64 and make `cmake`, `g++`, `windres`, and `mingw32-make` available on `PATH`. To use an existing checkout, set `GODOT_CPP_SOURCE_DIR` to its path before launching Godot, or place it at `native/hit/godot-cpp`.

Build once per target platform with its native toolchain. Windows uses the `MinGW Makefiles` generator and `build/Windows-mingw`; Linux uses `Unix Makefiles` and `build/Linux`. CMake places both the platform-specific `godot-cpp` archive (`libgodot-cpp.*.a`) and HitManager extension in the repository's top-level `bin/` folder. Windows produces `bin/hit_manager_combat.windows.template_debug.x86_64.dll`; Linux produces `bin/libhit_manager_combat.linux.template_debug.x86_64.so`. The combat-specific filename lets an editor that still has the previous native library loaded keep running while CMake builds the updated version. Binaries and CMake build directories are generated files and are not committed. Exported builds also need the matching prebuilt release library; the editor startup builder only creates the debug library for the current platform.

Close running Combat instances before subsequent Windows rebuilds: a process loading the current DLL locks that file. The filename change above only avoided the previous filename during this migration.

`HIT_MANAGER_OPTIMIZE` defaults ON. GNU/Clang contact code uses `-O2` even with a Debug/template_debug ABI, retaining debug symbols/assertions and avoiding fast-math. The editor startup builder explicitly requests it. A manual CMake configure with `-DHIT_MANAGER_OPTIMIZE=OFF` provides unoptimized contact code for debugging; editor startup restores its optimized default. This option does not change Godot's version or export configuration. Linux GCC compilation/load is now verified; MSVC remains unverified.

The startup builder now passes an explicit processor count to `--parallel`; bare `--parallel` becomes unbounded `make -j` on Linux. The extension's `ARCHIVE_OUTPUT_DIRECTORY` also points to root `bin/`, so Windows now places `libhit_manager_combat.windows.template_debug.x86_64.dll.a` beside the DLL and godot-cpp archive. Existing intermediate outputs are preserved, but the current configured artifact destinations are root `bin/`.

Pooled piercing transport is provided by `CombatProjectileData`, `CombatProjectile` and `CombatProjectilePool`. Data must explicitly supply a valid HitSpec, profile, speed and lifetime; defaults remain unconfigured. A flight snapshots its data, submits world poses through HitboxProxy, and resolves native contacts normally. It never refreshes its native hit set. Pool reuse unregisters the previous flight and allocates a fresh native ID, preventing stale hits or teleport sweeps. Inactive objects are cached, bounded by pool capacity and the native 1024-hitbox cap. A completed-step serial prevents a projectile spawned during hit resolution losing a lifetime tick before its first query. Lifetime cleanup occurs after the contact-step signal, outside that signal's precomputed callback timing. Thirteen tests cover piercing, reuse, tiny-target sweep, masks/data/source identity, bounds, cleanup, rebind, deactivation and refresh rejection. Actual Saber's automatic charge/emission and hit relationship remain source-gated; transport tests are not acceptance of that special behavior.

Profile API: `configure_hitbox(id, shape, size, linger_ticks, decay_samples)` and `set_hitbox_transform(id, transform)`. Sphere uses `size.x` as radius; capsule uses `size.x` as radius and `size.z` as centerline length along local Z; box uses full XYZ dimensions; cone uses `size.x` as half-angle in degrees and `size.z` as length along local -Z; ring uses radius/thickness/full height in XYZ around local Y. These define the geometry data schema; authored weapon dimensions remain playtest tuning. Decay samples are interpolated over normalized trail age. History is capped at 256 ticks and decay data at 257 samples.

Hitbox collision masks filter the hurtbox layer bitfield. Scene hitbox IDs are allocated by the manager, and hurtbox positions are submitted in one batch before each native step. Limits are 8192 registered hurtboxes and 1024 hitboxes; each hit-once set is bounded by the live hurtbox registry, and unregister removes that ID from all hit sets. Excess hurtbox registrations return -1; excess hitbox configuration is rejected. Unknown activation/pose calls do not create registry entries.

The scene adapter creates one proxy per HitSpec for each attack instance. ComboRunner's monotonic attack serial distinguishes re-entry into the same graph node. Retired attack proxies keep their original specs while trails finish, then unregister; refresh ticks are applied once per proxy/tick. Decay baking is bounded to the native sample limit.

Revolver requests leave the controller through `revolver_shot_requested`. The scene adapter submits current hurtbox poses, queries the native registry with its layer mask, and resolves the returned combatant through the same HitResolver as melee. A valid registered locked target in range takes priority; otherwise the nearest center inside the aim cone is selected. A zero cone requests an unassisted ray/capsule test. The request uses RangedWeaponData for damage, Heat, ammo timing/capacity, and airborne hold; CombatTuning provides default ammo values when no weapon data is supplied. The 15-degree adapter aim cone remains placeholder tuning inherited from the prototype.

The hurtbox registry stores IDs, positions, radii, heights, and layers in separate contiguous arrays. A bounded ID-to-slot index supports updates; removal moves the last slot into the removed slot and repairs its index. IDs remain stable across that compaction. Hit processing and ray queries iterate packed slots. Native hurtbox position is the capsule base; Godot HurtboxProxy transforms locate the capsule center. HitManagerNode subtracts half the world-space height when registering and batching proxy positions. Combat centers and visual meshes remain centered on the proxy.

Each `step()` contact returns the exact stored trail sample that produced it: `transform` is the evaluated hitbox pose at contact, `previous_transform` is that sample's starting pose, `swept` distinguishes continuous motion from a stationary sample, and `trail_age` identifies linger age. Swept sphere contacts report the closest evaluated centerline pose; other swept profiles report the evaluated pose selected by conservative advancement. Sphere `position` is the midpoint between the nearest hit-sphere and hurt-capsule surfaces (the surfaces coincide at tangency); other profiles retain their native geometric contact point. GDScript copies this data into `HitContactContext` before defense callbacks can retire the hitbox; if a native pose is absent, the context marks it unavailable instead of substituting the newest proxy transform.

Opt-in `get_debug_snapshot()` returns `{hurtboxes, hitboxes}` without advancing state or refreshing hit sets. Hurtbox entries contain native ID, base position, radius, height and layer. Visible hitbox entries contain ID, shape, size, mask, active flag and their actual native pose history; each pose includes transform, previous transform, swept flag, age and baked potency. Empty histories are omitted. This allocates diagnostics only on demand and adds no snapshot work to `step()`. The lab's optional Hit/trail and Hurtbox toggles render those values, stripping pose scale to match native world-size semantics. Green is live, orange is an aging trail and magenta connects swept pose origins; this path is a diagnostic line, not a sampled swept contact volume. Gizmos remain readable while paused and are disabled in benchmarks. Worst-case diagnostic rendering cost is not a production hit-system performance claim.

Profile dimensions are world-space sizes. Poses contribute translation and orthonormal orientation; inherited model scale does not resize the native volume. Sphere/capsule dimensions already used this contract; box/cone/ring now use the same rigid-pose convention.

Pose submission now canonicalizes orientation once, so model scale changes alone do not create native sweep work. Stored trail poses cache their start/end rotations, angular displacement and translation length; these are reused for all targets. Profile radius is applied at query time, preserving correctness if a profile is reconfigured while history exists. Rigid inverse queries use the transposed orientation. The cache adds about 48 bytes per stored pose (bounded by the existing history/registry caps), not an unbounded target cache. Cone distance queries use proven convex endpoint minima or an already-contacting centerline point before the unchanged 32-level interior search. Sweep tolerance and the 1024-iteration safeguard remain unchanged.

Sphere sweeps use continuous segment-to-capsule distance, including the swept segment at each lingering trail age. Box/capsule distance minimizes the piecewise quadratic over the complete capsule axis. Finite-cone distance uses its triangular radial cross-section and a bounded numerical minimization over the capsule axis. Regression cases cover a tiny target between old sweep samples, long capsule crossings away from endpoints/midpoint, rotated box extents, box corners, cone side/base corners, and lingering swept potency.

Ring volume is a finite annular cylinder. Its capsule-axis distance minimization partitions at radial/height boundaries, radial extrema, and inner-hole derivative inflections, then checks interval stationary points. This replaces the three-point capsule approximation. Tests cover long/rotated axes, center-hole exclusion, combined radial/height corners, and 64 deterministic comparisons against a dense reference with a sampling-error bound.

Non-sphere sweeps use continuous conservative advancement based on measured separation and a translation-plus-angular-motion bound. A rotation-axis projection rejects separated thin volumes; pure translating convex profiles use a convex time search if advancement becomes slow. Translation interpolation uses double intermediate arithmetic. The contact tolerance is 0.00001 world units and each query has a 1024-iteration safety budget. Exhaustion logs a warning, increments `get_sweep_exhaustions()`, and returns no contact; it is not treated as a verified ordinary miss. Tests cover 2000-unit crossings of tiny targets, near-half-turn rotation-only contacts for each profile, and long thin-box parallel near misses, all with zero observed exhaustion.

Current limitations: pathological grazing motions, finite-precision boundaries, and the iteration-budget limit still need broader acceptance evidence. Gameplay camera/muzzle alignment, full query boundary coverage, and human targeting feel remain unverified.

Append `-- --combat-profile=capsule` (or `sphere`, `box`, `cone`, `ring`) to the **console command** to select a synthetic profile. The benchmark counts 600 completed native steps, rotates the profile while moving it, and prints sweep exhaustion count. Its dimensions are synthetic tuning, not authored weapon performance evidence. Authored benchmarks are `Scenes/CombatBenchmarkMantis.tscn` and `Scenes/CombatBenchmarkLance.tscn`. They drive the actual Player/weapon graphs through 120 warmup + 600 measured completed steps against 200 persistent dummies, write JSON to ignored `native/hit/build/`, and exit. They include native, full contact-callback, real frame-wall and coarse engine CPU timing scopes, per-node native timing, actual contacts/movement, platform and target-verification flags.
